# 视频视觉适配层

本文件定义视频生产如何复用 Guizang social card 的视觉内核。它只约束工作区内的视频适配，不修改 `design/guizang-social-card` 的原始快照。

## V1 范围

- 主画幅：3:4（默认 1080×1440）。
- 预留画幅：16:9（1920×1080）与 9:16（1080×1920）。
- 兼容画幅：4:3（1440×1080），只在明确要求时启用。
- 风格模式：Editorial Magazine × E-ink 或 Swiss International；每条视频默认只选一种模式。
- 动画：静态卡片轻动效。运动不能改变已经确认的版式层级。

Social card 快照原生提供 3:4、1:1 与 21:9 的卡片体系。16:9、9:16 和 4:3 复用其 style system、theme、components、image treatment 与 recipe 语义，但必须建立各自的布局几何，不能盲目裁切 3:4 页面。

## 责任边界

内容策划决定一幕要表达的观点、证据和时长；视觉适配器把它映射为一个明确的 `style_mode + theme + ratio + recipe`；视频层只负责运动、旁白、字幕、音乐和导出。

静态场景图必须先渲染并通过检查，再加入运动和音频。视频渲染阶段不得重新安排标题、图片比例或组件层级。

## 场景类型

V1 使用以下语义场景类型，并为 3:4 先提供实现：

| 类型 | 主要任务 | 常用视觉关系 |
| --- | --- | --- |
| `cover` | 开场与主题建立 | 强主视觉 + 短标题 |
| `statement` | 传达一句结论 | 大字 + 克制辅助元素 |
| `evidence` | 展示截图、产品或事实 | 证据图为主，文字解释从属 |
| `comparison` | 展示前后、差异或选项 | 两区或多区对照 |
| `process` | 展示步骤或过程 | 顺序关系、编号或时间线 |
| `recap` | 收束一段内容 | 结论、要点或下一步 |
| `outro` | 固定品牌片尾 | 只使用确认过的固定组件 |

每一幕必须先选择场景类型和 recipe，再实现 HTML/CSS。没有 recipe 的自由排版不能进入正式视频渲染。

## 比例规则

同一份内容可以跨比例复用，但每个比例单独排版：

- **3:4**：当前生产标准。优先使用上方标题、中部主视觉、底部结论或字幕安全区的结构。
- **16:9**：预留横向适配。优先使用左右关系，避免把 3:4 纵向堆叠压扁。
- **9:16**：预留竖向适配。优先使用顶部标题、中部主体、底部字幕安全区，单独处理主体裁切。
- **4:3**：兼容输出。沿用 16:9 的横向逻辑，但收紧左右边距和信息数量。

所有比例都必须保留：标题安全区、主体焦点、字幕安全区、底部片尾区和最小可读字号。比例转换只复用语义和组件，不复用未经检查的绝对坐标。

## 风格与主题

Editorial 使用 `ink-classic`、`indigo-porcelain`、`forest-ink`、`kraft-paper`、`dune`、`midnight-ink`；Swiss 使用 `ikb`、`lemon-yellow`、`lemon-green`、`safety-orange`。风格模式可以按项目选择，单条视频内部不要无理由混合两套排版语法。

## 轻动效白名单

允许的 V1 动效：`static`、`fade-in`、`slow-pan`、`slow-zoom`、`line-reveal`、`step-reveal`、`number-count`。

动效只改变出现顺序、透明度、轻微位置或缩放；不改变标题位置、图片容器比例、字幕安全区、主体裁切和信息层级。若动效需要改变这些内容，应回到静态 recipe 重新排版。

## 静态场景验收

进入视频渲染前，逐幕检查：

1. 标题在缩略图尺寸仍可读，且与下一内容块保持明确间距。
2. 图片主体、脸部、产品细节和截图关键文字没有被裁掉。
3. 字幕安全区没有覆盖关键视觉信息。
4. 页面没有无理由的大块空白，也没有多组元素争夺同一视觉中心。
5. 相邻场景在 style、theme、字体和间距上连续，构图可以有节奏变化。
6. 固定片尾使用确认过的通用组件，不重新设计或按型号改写旁白。
