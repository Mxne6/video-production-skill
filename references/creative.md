# 内容策划：一份计划驱动整片

本文件只决定讲什么、先后顺序、画面与声音的分工。构图判断见 composition-system.md，排版执行及交接见 design-inheritance.md，图像任务及制作见 visual-planning.md；不在这些阶段各自重做一套故事。

## 规格与取舍

先解析来源、观众、用途、画幅和目标时长，已有明确要求不再询问。只给产品名称时先查询知识库。目标时长包含固定片尾、停顿和阅读留白；正文不能独占全部预算。区分“约 30 秒”与“严格不超过 30 秒”。将要求写入 project.json.duration：max 为严格上限，approx 为近似目标。工具在配音前检查估时预算，导出时检查真实时长；估时超限先删改内容，不靠后期加速救场。

围绕观众的一个问题组织现象、解释、证据和实际意义。按资料选择对比、过程、应用或产品介绍，不固定“开场口号→三点→总结”，不按 TDS 栏目逐页搬运，也不预设幕数、每幕字数或等长切片。六个命名 scene starter 不是内容分类表；策划阶段不需要决定“这一幕属于哪个模板”。重复合并，次要细节移出主线；为了凑时长或凑结构不得拆散、重复或编造内容。英语项目按英语稿独立策划，不能把中文项目的幕数和页面结构直接平移。

初始估时可参考每秒 3.5–4.5 个中文可读字符，再考虑英文型号读音、停顿与画面理解时间。标清估时依据；真实时长以音频为准。超时先删重复和次要信息，不盲目加速或截断音轨。

## 逐幕计划

使用已有 scenes[] 字段，不另设表单。intent 写观众要理解的一点；visual_notes 写画面重点和旁白补充内容；narration 是完整自然语义段；visual_plan 写媒介与理由，estimated_duration 记录包含停顿和尾部留白的估时。content_kind 分类覆盖本幕旁白、页面和图片的事实表达；factual 绑定 claim_ids，无事实陈述则写 nonfactual_reason。来源 claims 绑定原文、位置和必要条件，不把内部证据编号写成观众文案。

画面突出对象、关系、关键词或证据，旁白补充解释与过渡，字幕跟随实际语音；不把旁白全文重复放进页面。旁白有主语、因果与衔接，不复读标题，也不堆口头语。先通读整稿检查连贯性，再核对每幕能否在预计时间内看懂。

一幕不必只有一张静态卡，可用局部揭示解释关系；动画仅服务注意力或状态变化，不做持续漂浮、眩光和无意义飞入。beats 使用已说完的原文前缀及真实词边界，规则见 project.md。

## 从内容计划到设计 brief

故事和旁白确定后，才进入 `scenes[].design`。这一层是为了阻止“先选版式，再塞内容”。

按顺序回答：

1. `message`：这一幕结束时，观众应该理解的一句话是什么？
2. `viewer_task`：观众是在识别对象、理解机理、比较差异、验证证据、接受结论，还是感受氛围？
3. `dominant`：第一眼必须看到的是 statement / image / product / number / relationship / process / evidence 中的哪一个？
4. `attention_order`：按真实观看顺序列 1–3 个注意点。
5. `on_screen` 与 `narration_only`：必须看见的留画面，需要听懂即可的留给旁白。
6. `image_role` 与 `visual_share`：图片是 hero、evidence、support、atmosphere 还是根本不需要？它应该占多少视觉面积？
7. 最后才写 `layout_family / layout_signature / composition_reason`。

不要从“mechanism scene”反推出三步卡片，也不要从“proof scene”反推出两行 KPI。一个机理可能最适合单张剖面图加两处标注；一组数据可能最适合一个巨型数字；一个应用可能最适合满幅现场照片；同一语义任务可以产生完全不同的构图。

## 开场选择

开场让观众进入讲解，发布封面让观众判断是否点击；不自动将封面或技术资料首页当作视频第一幕。按内容选择切入点，而不是按产品类别固定套 opening starter：

- 问题/场景：有具体且资料支持的问题时，以问题和一个有用视觉主体建立关注点，型号辅助识别。不强制疑问句、不制造焦虑。
- 产品亮相：本期任务就是介绍型号，或有值得展示的产品主视觉时，产品身份配一句具体用途。可突出型号，但不能只靠大型号、分类和空泛关键词填满画面。
- 作用/关系：资料支持时直接展示一个作用或关系，示意不冒充实测，不编造效果倍率。

先在第一幕写切入理由、首要信息、视觉任务、声音补充与停留时间，再决定构图。型号尽量完整呈现，不为了大字机械拆开；首幕不同时铺开机理、用途清单和参数。短标题与一处辅助身份通常足够，具体字量按时间与可读性决定。

## 整片节奏

策划时同时看整条叙事的视觉能量，而不是逐幕孤立优化。setup、reveal、proof、explanation、consequence、closure 可以自然对应不同强度，但不能为了“每页不一样”随机换版。

- dense → dense → dense 只有在内容确实持续升级时才合理；
- 强图片之后可以接安静的 typography / data scene，让眼睛恢复；
- 连续展示同一对象状态时可以故意复用结构，但要记录 continuity_reason，让重复服务比较；
- 如果连续三幕的视觉主角、占幅、标题位置和大矩形轮廓都一样，即使每幕内容不同，也应重新构图。

## 固定片尾与审核

新义合成片尾由 brand-outro.md 的组件承担，首次分镜即纳入总时长。画面只填本期信息，旁白采用固定文案，并与正文一起纳入整稿确认和正常 TTS 流程，不另起创作阶段。

首轮集中交付稿件、分镜、时长、代表画面与缺图清单。用户反馈按具体范围修改，已有有效授权保留。画面有变可重做图和布局而不重配未变声音；字幕切分有变不重做音频。审阅应回答“观众得到什么、第一眼是否正确、重复能否删除、声音与画面是否争抢注意力、相邻 scene 是否机械重复”，不能以无溢出代替内容或设计判断。
