# 视觉与素材：先决定视觉角色，再决定图槽

执行 creative.md 已确定的逐幕计划，并先完成 composition-system.md 的 scene design brief；排版和技术交接走 design-inheritance.md。每幕在 visual_plan 记录 medium 和帮助理解的理由，在 scenes[].design 记录真正决定构图的 dominant、image_role、visual_share 与 attention_order。不得以“丰富画面”代替视觉任务。

新义合成竖版正文默认从 `adaptive` seed 开始。旧的 `opening / product-hero / mechanism / proof-data / application / summary` 只在内容与其结构天然吻合时作为 starter，不能作为“内容分类 → 模板”的自动映射。即便用了 named starter，也必须服从 scene design brief；如果主角改变，就可以重写绝大部分 DOM。

## 图片不是槽位，而是构图变量

**整片可以有很多图，也可以某一幕完全无图；每张图都必须改变理解方式，而不是只改变填充物。**

先判断图片角色：

- `hero`：图片本身就是第一信息。通常应拥有约 55–85% 的有效画布，标题和说明围绕主体、quiet zone 或边缘组织。
- `evidence`：测试结果、截图、工程照片等是论据。必须大到可检查，并与它证明的 claim 空间上靠近。
- `support`：图片回答一个具体次级问题，可以较小，但不能只是“让画面别太空”。
- `atmosphere`：仅用于建立环境、节奏或情绪；事实仍由旁白/文字承担。开场、转折、收束可用，不能滥用。
- `none`：没有有用图片时明确不用，不设图片配额。

如果数字最重要，让数字成为空间事件；如果一句话最重要，让 typography 和有意义的留白成为主体；如果关系最重要，让关系的方向、距离、顺序、分组或重叠决定几何；不要把它们都压进同一种容器。

图片位置、占幅和目标比例随内容选择，可整屏、半屏、竖长侧栏、横向证据带、多图对照、局部材料窗，也可连续多幕用图。图片是主角时先给足空间，再安排必要文字。

## 配图判断与生成

按产品对象、机理、关系、材质、应用或操作需要，自主调用 image2。支持制作场景照片、材质近景、概念插画、剖面/关系示意和完整信息图，不把生成能力限制为文字旁的小配图。

**图片尺寸由最终构图决定，不由素材原始尺寸决定。**先在 design brief 中确定角色和 visual_share，再在 HTML 构图中确定实际显示框比例、主体 safe zone 与目标像素尺寸，最后制作/选择图片。原图比例必须与显示意图兼容；`object-fit: cover` 只能在裁切不会破坏主体和证据时使用。比例不合适时优先改构图、重新生成、重新构图或用 `contain`，不能把主体硬裁掉。

真实产品/包装、Logo、工程照片和实测图表优先使用原件。生成图可解释抽象概念或应用环境，不能冒充产品实拍、真实案例或实测数据。根据“什么东西只听旁白仍然难理解”选择配图，而不是因为排字方便跳过有用图片。

当文字压在照片上时，继承 Guizang 的核心方法而不是照搬社交卡 recipe：先识别主体与 quiet zone，再决定文字区域和 object-position；默认先不用全幅遮罩，只有缩略图可读性失败时才做局部、与图像色调一致的 tint。照片不适合压字就换 framed / split 构图，不强救。

## 素材执行与登记

需要的图写入 scenes[].assets，项目 assets[] 保存 id、status、path、source、purpose、prompt、ratio、source_pixels、render_slot、composition、factual_constraints、sha256。render_slot 应描述真实构图职责（如 `hero 68% upper field`、`evidence strip 4:3`），不只写“右侧图片”。三者与实际画面不一致时不得标记 ready。未到位图可用于有明确标记的布局占位，不能报告为正式完成。

- 用户素材：保留原件、核对身份与用途，按主体决定完整展示或有意裁切。新义合成 Logo 的唯一默认原件见 brand-outro.md。
- 自主生图：使用可用 imagegen 工具及其 Skill；提示词包含任务、主体/动作或关系、构图比例、文字和字幕安全区、事实限制。用户要求 image2 时按工具提供的模型控制执行，工具未暴露实际模型则如实记录，不虚称验证了版本。无需把逐图决策交回用户。
- 外部图片：仅用户明确选择时交完整可复制提示词并等待返图；工具不可用则记录阻塞和可继续的准备，不能暗中将外部模式作为默认交付。状态用 waiting_external / ready 区分。

生成/接收后先看实际图，再核对清晰度、工具接触、手部、意外文字、主体裁切、quiet zone 和它是否真的能承担预定角色。不合格的针对问题修改，不把提示词当成成图事实。素材复制入项目后记录哈希，使用 `<img data-asset-id="素材ID">` 接入；主体/关键文字用 data-safe-check 标记。用于检查的图片层不用不可定位的 CSS 背景替代。

## 内容真实性

为图写一句预期解释及来源；再不看图注判断画面本身的含义，核对对象、动作、阶段、因果、数量、单位、刻度和高亮范围。不暗示来源没有的施工步骤、倍率、实验状态或适用结论。例如颗粒图变成加水工序、时间盘看起来像强度百分比，都须改图而非只加“示意”。缺可靠依据时换表达或补核实，不编造证据。

示意需要时简短标注“场景示意 / AI生成”；标注不是免核验声明。生成图保存 semantic_review：status、asset_sha256、intended_message、source_refs、observed_content、misreading_check，记录实际观察，不泛写“正确”。改图后原核验失效；失败图记 rejected。模型核验不新增用户逐图审批，工具仅验证记录与文件绑定，不负责科学判断。

## 视频页面约定

- 顶部信息栏不是默认必需。只有分类/章节定位真的帮助观看时才保留一处；不要让每幕都因为 rail 而拥有同一轮廓。
- 底部不重复添加产品名、公司名、年份、场景编号或 SOURCE/claim ID。必要图注、图片署名、用量基准及适用条件保留，不当装饰。
- 底部留给真实字幕和阅读呼吸空间。网格用于对齐，不显示通页网格、调试线或舞台框；分隔关系所需的线、坐标和箭头可以保留。
- 不依赖大量圆角 card、SaaS matrix、Dashboard widget 建层级。优先使用尺度、位置、对齐、规则线、列、图像和真正的数据关系。
- 图片与内容块大小服务手机阅读，不把主视觉缩进小图标框。修改旧页面要改生成器并重建对应 HTML/PNG，不能只修截图或期望新规则自动更新旧文件。

## 静态设计与整片节奏检查

单幕先通过静态设计，再做 motion：

1. 全尺寸看：主体、裁切、层级、事实和字幕安全区；
2. 缩到约 360px 宽看：第一眼是否仍是 declared dominant，标题和关键数字是否还成立；
3. 与前后 scene 放在 contact sheet 看：大矩形轮廓、标题位置、图片占幅、密度与强度是否机械重复；
4. 如果 attention_order 不对，优先改变几何与尺度，不先加颜色、阴影或动画。

`python scripts/scene_design.py P` 检查 design brief 与基本 sequence rhythm。它只能抓显式重复和信息预算问题，不能替代视觉判断。连续三幕同一 layout_signature 默认失败；若确实为了同对象对比而重复，写 continuity_reason。

## 技术预检与局部更新

`python scripts/visual_review.py P --render` 生成估时预览，核对视觉计划、图片解码/哈希/可见性/来源、反向 seek，并用 caption_phrases 和正式字幕样式检查最长字幕的宽度和遮挡。查看报告及实际截图后才继续。预检不是正式音频时间戳或真人同步审核，程序通过也不证明构图好看。

改变图片、裁切、scene design、HTML 或样式后更新依赖和哈希，仅重查受影响页面；未变旁白继续复用。真实视听核验与正式导出按 runtime.md。
