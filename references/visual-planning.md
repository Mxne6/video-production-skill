# 视觉与素材：图片各有任务，画面保持清楚

执行 creative.md 已确定的逐幕计划，版式和技术交接走 design-inheritance.md。每幕在 visual_plan 记录 medium（typography / diagram / image / mixed）和帮助理解的理由，不以“丰富画面”代替任务。

## Guizang 视觉内核与画幅适配

视频场景遵循 [视频视觉适配层](video-visual-adapter.md)：3:4 是当前默认主画幅；16:9、9:16 与 4:3 只复用语义和组件，必须分别排版。每幕先选择 `style_mode + theme + ratio + recipe`，再写 HTML。不得把 3:4 页面直接裁切成其他比例。

先生成静态场景 PNG，单独查看并完成设计审核，再加入 `static`、`fade-in`、`slow-pan`、`slow-zoom`、`line-reveal`、`step-reveal` 或 `number-count` 等轻动效。运动只改变出现方式、透明度、轻微位移或缩放，不改变标题位置、图片比例、字幕安全区和信息层级。

每幕的 `subtitle_safe_area`、`focal_point` 与预计时长必须在视觉计划中可定位。相邻场景可以更换构图，但 style、字体、主题和间距要连续；不要连续使用同一种构图，也不要为了填密度增加重复卡片或装饰。

## 配图判断与生成

**整片有图，但每张图都要有任务；图片服务于讲解，而不是讲解迁就图片。**正文不能全是排字，封面、Logo、片尾截图不能充数；一幕已经有图不等于其他幕的视觉任务已经完成。也不固定张数、不强制每幕配图，更不能为凑图改变讲解。

按产品对象、机理、关系、材质、应用或操作需要，自主调用 image2。位置、占幅和目标比例随内容选择，不默认第二幕或右侧横图，可整屏、半屏、竖长侧栏、横向带状、多图组合，也可连续多幕用图。支持按用途制作场景照片、材质近景、概念插画、剖面/关系示意和完整信息图，不把生成能力限制为文字旁的小配图。图片是主角时先给足空间，再安排必要文字。

图片可承载完整主视觉与准确文字，但仍遵循整片主题和字幕区域，不叠加重复的 HTML 标题与说明。目标比例灵活设计，实际输出尺寸按工具支持；提示词提前安排裁切安全区，不拉伸主体、裁掉重要关系或声称未验证的精确尺寸。

真实产品/包装、Logo、工程照片和实测图表优先使用原件。生成图可解释抽象概念或应用环境，不能冒充产品实拍、真实案例或实测数据。根据文字难以看清的对象/关系选择配图，而不是因为排字方便跳过有用图片。

## 素材执行与登记

需要的图写入 scenes[].assets，项目 assets[] 保存 id、status、path、source、purpose、prompt、ratio、composition、factual_constraints、sha256。比例和构图字段填写本图的实际计划，不复制某个固定示例。未到位图可用于有明确标记的布局占位，不能报告为正式完成。

- 用户素材：保留原件、核对身份与用途，按主体选择 contain 或裁切位置。新义合成 Logo 的唯一默认原件见 brand-outro.md。
- 自主生图：使用可用 imagegen 工具及其 Skill；提示词包含任务、主体/动作或关系、构图比例、文字和字幕安全区、事实限制。用户要求 image2 时按工具提供的模型控制执行，工具未暴露实际模型则如实记录，不虚称验证了版本。无需把逐图决策交回用户。
- 外部图片：仅用户明确选择时交完整可复制提示词并等待返图；工具不可用则记录阻塞和可继续的准备，不能暗中将外部模式作为默认交付。状态用 waiting_external / ready 区分。

生成/接收后先看实际图，再核对清晰度、工具接触、手部、意外文字与主体裁切。不合格的针对问题修改，不把提示词当成成图事实。素材复制入项目后记录哈希，使用 `<img data-asset-id="素材ID">` 接入；主体/关键文字用 data-safe-check 标记。用于检查的图片层不用不可定位的 CSS 背景替代。

## 内容真实性

为图写一句预期解释及来源；再不看图注判断画面本身的含义，核对对象、动作、阶段、因果、数量、单位、刻度和高亮范围。不暗示来源没有的施工步骤、倍率、实验状态或适用结论。例如颗粒图变成加水工序、时间盘看起来像强度百分比，都须改图而非只加“示意”。缺可靠依据时换表达或补核实，不编造证据。

示意需要时简短标注“场景示意 / AI生成”；标注不是免核验声明。生成图保存 semantic_review：status、asset_sha256、intended_message、source_refs、observed_content、misreading_check，记录实际观察，不泛写“正确”。改图后原核验失效；失败图记 rejected。模型核验不新增用户逐图审批，工具仅验证记录与文件绑定，不负责科学判断。

## 视频页面约定

- 顶部最多一条信息栏：将第二行有意义的主题移入最上方，保留原细字、字距、对齐及细分隔线；删除重复分类。同义分类可省略，正文标题和必要副标题保留。日期、中英双写不默认添加，页码有用途时只留一处。
- 底部不重复添加产品名、公司名、年份、场景编号或 SOURCE/claim ID。TDS/内部审核语言放记录或审核页外层。必要图注、图片署名、用量基准及适用条件保留，不当作装饰页脚删除。
- 底部留给真实字幕和阅读呼吸空间。网格用于对齐，不显示通页网格、调试线或舞台框；分隔关系所需的线、坐标和箭头可保留。不要为密度提示填重复卡片或摘要条，处理方法见 design-inheritance.md。
- 图片与内容块大小服务手机阅读，不把主视觉缩进小图标框。首幕核对主题是否快速可识别、在预计时间内能否读完、画面与声音是否互补。修改旧页面要改生成器并重建对应 HTML/PNG，不能只修截图或期望新规则自动更新旧文件。

## 技术预检与局部更新

`python scripts/visual_review.py P --render` 生成估时预览，核对视觉计划、图片解码/哈希/可见性/来源、反向 seek，并用 caption_phrases 和正式字幕样式检查最长字幕的宽度和遮挡。查看报告及实际截图后才继续。预检不是正式音频时间戳或真人同步审核，程序通过也不证明构图有用。

改变图片、裁切、样式后更新依赖和哈希，仅重查受影响页面；未变旁白继续复用。当前工具不会自动判断每张图的内容任务，也没有整片无正文配图的完整自动拦截，执行者须核对这些要求。真实视听核验与正式导出按 runtime.md。
