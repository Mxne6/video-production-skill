# Skill 维护阶段的子 Agent 分工

本文件约束“设计和改造这个 Skill”时如何使用低成本子 Agent。它与视频正式生产阶段的 worker 分层不同，但遵守同一成本原则：主 Agent 掌控全局，低成本 Agent 处理边界清楚的机械工作。

## 主 Agent 保留的工作

- 把用户意图转成 Skill 架构、阶段入口和输入输出契约；
- 决定哪些规则是硬约束，哪些只是建议；
- 选择文件边界、兼容策略、迁移策略和验收标准；
- 判断设计质量、用户体验、跨文件一致性和风险；
- 汇总子 Agent 结果，决定是否采纳；
- 处理需要用户选择的事项，不让子 Agent 代替用户确认。

## 低成本子 Agent 可执行的工作

只有在任务输入已经冻结后才委派：

- 枚举文件、查找引用、检查文档链接；
- 运行语法检查、JSON 校验、单元测试和差异检查；
- 比较工作区源码与安装副本哈希；
- 按主 Agent 提供的精确替换范围做重复性文档同步；
- 整理测试输出、文件清单、失败路径和复现命令；
- 对固定格式的 manifest、样例和索引做机械更新。

低成本子 Agent 不负责：

- 重新设计 Skill 架构；
- 选择风格、recipe、模型或成本策略；
- 自行扩大修改范围；
- 根据审美判断重写页面；
- 把测试通过解释为视觉、听感或用户验收通过；
- 自动升级到更强模型。

## 委派任务包

每个子任务都应明确：

- task_id、目标、允许读取/修改的文件；
- 禁止做出的产品或架构决策；
- 输入文件、命令、期望输出和失败停止条件；
- 实际模型、推理档位、用量来源和重试次数；
- interventions、输出文件哈希和主 Agent 验收结果。

子 Agent 返回结构化结果，不直接向用户宣布项目完成。遇到不确定事项时返回 blocked 和证据，由主 Agent 决定下一步。主 Agent 不能把未检查的子 Agent 结论当作事实。

## 并行和验收

只有互不共享写入状态的任务才并行。涉及同一文件的编辑、依赖上一步结果的任务和用户反馈必须由主 Agent 顺序处理。主 Agent 收到结果后重新运行必要检查，并记录实际采用的改动和介入。
